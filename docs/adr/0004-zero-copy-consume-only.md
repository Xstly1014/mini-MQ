# 4. 零拷贝仅用于消费路径（FileRegion/sendfile），生产路径保留用户态

- Date: 2026-10-16 (M2)
- Status: Accepted

## Context

"零拷贝"在消息队列语境里指发送文件到网络时省掉内核态↔用户态的来回拷贝（sendfile /
FileRegion）。生产路径必须：追加写 CommitLog、计算 CRC、更新稀疏索引、组提交记账——
数据必然进用户态，"生产侧零拷贝"在语义上不成立。消费路径是只读的：mmap 页缓存命中区 →
网卡，可以直通。另外 Windows 上 FileRegion 有官方警告的性能洼地（M2 实测记录在案）。

## Decision

消费 FETCH 走 FileRegion 零拷贝直通（页缓存命中区，响应帧仍需用户态写帧头）；生产路径
保留用户态编码（CRC/索引/记账语义决定其不可避）。基准环境统一 WSL2 Linux（Windows 洼地
如实记录，不作为基准口径——与 ADR-0008 联动）。

否决的备选：

- **生产侧零拷贝**：写 + 索引 + CRC 语义不成立，否决的不是优化而是概念误用。
- **全平台无差别 FileRegion**：Windows 行为失真会把基准数字变成"平台 bug 的测量"，跨平台
  结论必须限定 Linux 口径。

## Consequences

- **+** 消费路径拷贝次数最小化：追尾消费 16 万 msg/s 平台；冷/追尾 4.7× 分离成为页缓存
  命中的行为证据（M5 全景）。
- **+** "零拷贝只配只读路径"这条边界在面试里比"我用了 sendfile"值钱——说得出不适用的一侧
  才算懂。
- **−** Windows 原生跑不出 Linux 口径的数字（诚实记录，不是缺陷）。
- **−** FileRegion 与帧编码共存需要小心拼装（帧头 + 文件区段的复合写），增加响应组装复杂度。
- **→ 失效边界**：若消费需要服务端过滤/重编码（非透传语义），零拷贝直通失效，退回用户态拷贝。
